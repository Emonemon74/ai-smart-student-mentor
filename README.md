# AI Smart Student Mentor (Trialshopy assignment)

Build contract: [docs/HLD.md](docs/HLD.md) and [docs/LLD.md](docs/LLD.md) for the first release, and [docs/HLD_next.md](docs/HLD_next.md) and [docs/LLD_next.md](docs/LLD_next.md) for the next release (v2: goals, concept check, levels, general mode, support path, review check-in). Synthetic data only.

## Prerequisites
Docker (running), [uv](https://docs.astral.sh/uv/), Node.js 20+ with npm, and optionally `cloudflared` for the phone hand-off (`brew install cloudflared`). Without it the phone link falls back to `PUBLIC_BASE_URL` (LAN or hotspot). You need at least one LLM key: a free Groq key is enough, and a second provider (for example Gemini) is used automatically if the first is rate limited.

## Setup
```bash
cp .env.example api/.env     # set ADMIN_PASSWORD (12+ chars), GROQ_API_KEY and GROQ_MODEL (optionally GEMINI_*, and COUNSELLOR_PASSWORD for the counsellor staff role)
docker compose up -d         # Postgres on host port 5433
cd api && uv sync && uv run python -m app.connector import seed --batch baseline && cd ..
cd web && npm install && cd ..
```
The bundled synthetic data is generated by `api/seed/gen.py` relative to a date written in `api/seed/ANCHOR`. When you import it, every date is moved forward by the days that have passed since then, so the upcoming internal is always still in the future and nobody is flagged with a "missing mark" because the data went stale. Add `--exact-dates` to the import command to keep the CSV dates as they are. Real data (any folder other than the bundled `api/seed`) is never shifted.

If something already uses port 8000 on your machine, add `API_PORT=8010` to `api/.env`. Pick non-reasoning chat models, because reasoning models can spend their token budget thinking and return an empty reply.

## Run the demo
```bash
./scripts/dev.sh             # Postgres, tunnel, API, web; prints the URLs
google-chrome --kiosk --user-data-dir=$HOME/.emon-kiosk http://localhost:3000
```
On macOS use `open -na "Google Chrome" --args --kiosk --user-data-dir=$HOME/.emon-kiosk http://localhost:3000`, or simply open http://localhost:3000 in a normal Chrome window. Allow the microphone once for `localhost:3000`.

Demo sequence: import baseline, run the student journey, scan the QR on a phone, then
`cd api && uv run python -m app.connector import seed --batch review` and open the report.

## Demo script (about 4 minutes, v2)
1. `./scripts/reset.sh` once after pulling v2 (the schema changed; it recreates the demo database with dated data), then `./scripts/dev.sh` and open the kiosk. Before a demo run `cd api && uv run python -m app.connector check-links`.
2. Sign in as `CS23001` / PIN `1234` (all 30 synthetic students use `1234`) and choose **Use my records**. Data Structures shows the prerequisite gap (Graphs starts at Foundation, from records) with a suggested response.
3. **Check my level** on Graphs: five questions, then the provisional level and an explanation for each question.
4. **Create my plan**: goal GATE preparation, subject Data Structures, a target date. Edit, then **Save plan**.
5. **Send to my phone**: scan the QR (single use, 10 minutes). Tick tasks on the phone; the Progress tab shows the report.
6. Review day: `cd api && uv run python -m app.connector import seed --batch review`. A "Ready for review" banner appears on the profile. Start the review: confidence, plan fit, a second Graphs check, then the report with verified marks, kiosk checks and your own ticks kept apart, indicators and next steps.
7. Sign in as `CS23002` and choose **Continue without my records** to show general guidance (goals, approved resources, mentor without records).
8. In the mentor, type "I feel so stressed". The support panel shows the contacts; **Request a private counsellor referral** sends it to the counsellor only.
9. Staff: `/admin` with `ADMIN_PASSWORD` (totals, metrics, request queue, health; wellbeing shows only as a count) and with `COUNSELLOR_PASSWORD` (the wellbeing queue only).

Other designed students: `CS23004` theory vs practice gap, `CS23005` pending backlog (backlog goal), `CS23006` low evidence, `CS23007` targeted gap.

Before any real use: the concept-check questions are marked `pending-faculty-review` and need faculty review, and the support contacts in `api/seed/contacts.json` are placeholders (verify the helpline number and wording).

Hindi: switch with the language button (UI strings and mentor replies).  Wellbeing worries are answered with a human-mentor referral, never counselling.

## Local port notes
Postgres is mapped to host port **5433** and the API defaults to port 8000 (set `API_PORT=8010` in `api/.env` if 8000 is busy).

## Tests
`cd api && uv run pytest`   (200+ tests; uses database `emon_test`, which is recreated from the schema on every run; the LLM is never called; includes the v1 and v2 demo journeys, each run twice)

## Reset
Clear sessions, plans, concept checks, reviews, requests, feedback and the audit log, and remove the imported review marks so the "review day" step works live again. The 30 students, baseline marks and resources are kept:
```bash
docker compose exec postgres psql -U emon -c "TRUNCATE sessions, roadmaps, tasks, share_tokens, requests, feedback, audit_log, diagnostics, reviews RESTART IDENTITY CASCADE; DELETE FROM assessments WHERE batch='review'; DELETE FROM attendance WHERE batch='review'; DELETE FROM backlogs WHERE batch='review'; DELETE FROM imports WHERE batch='review';"
```

## End of semester

Saved plans are cleared at semester end (HLD §9). This deletes all plans, tasks, concept checks, share links and phone sessions, and keeps student records:

```bash
cd api && uv run python -m app.connector end-semester
```
